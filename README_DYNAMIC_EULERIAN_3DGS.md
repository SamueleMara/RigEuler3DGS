# Adaptive Eulerian Dynamic 3DGS Patch

This patch extends the standard GraphDeco/Inria 3D Gaussian Splatting codebase with a two-stage dynamic training mode:

1. **Static canonical 3DGS training** on the vanilla COLMAP frame-000000 dataset.
2. **Eulerian velocity-field training** over the following multiview RGB-D frames, while keeping the CUDA rasterizer unchanged.

The renderer still receives ordinary Gaussian tensors. Dynamic motion is injected before rendering by advecting canonical Gaussian centers through a learned world-fixed velocity field.

---

## Expected dataset layout

Your current SAPIEN layout is supported directly:

```text
USB_100109/
  colmap/
    images/
    sparse/0/
      cameras.bin
      cameras.txt
      images.bin
      images.txt
      points3D.bin
      points3D.txt
  rgb/
    cam_000/frame_000000.png
    cam_000/frame_000001.png
    ...
    cam_007/frame_000059.png
  depth_npy/                 # optional
    cam_000/frame_000000.npy
    ...
  depth_png/                 # optional
    cam_000/frame_000000.png
    ...
  dinov3/                    # optional, generated by tools/extract_dinov3_features.py
    cam_000/frame_000000.pt
    cam_000/frame_000001.pt
    ...
  metadata/
  pointcloud/
```

The `colmap/` directory is used exactly as vanilla 3DGS. The dynamic reader only clones the fixed COLMAP camera poses over `rgb/cam_xxx/frame_yyyyyy.png`.

## Training schedule

The new default training split is:

```text
static_train_iters = 30000
euler_field_train_iters = 10000
```

### Stage A — static canonical 3DGS

Iterations: `1 ... static_train_iters`

Uses the vanilla COLMAP dataset in:

```text
USB_100109/colmap/images
USB_100109/colmap/sparse/0
```

This stage is standard 3DGS:

- optimize Gaussian centers;
- optimize SH appearance;
- optimize opacity;
- optimize scale/rotation;
- use standard densification/pruning;
- optionally use depth if the vanilla COLMAP image set has depth configured.

### Stage B — Eulerian velocity-field training

Iterations: `static_train_iters + 1 ... static_train_iters + euler_field_train_iters`

Uses the dynamic multiview sequence:

```text
USB_100109/rgb/cam_xxx/frame_yyyyyy.png
```

By default the dynamic frame range starts at `frame_000001`, because `frame_000000` is the canonical static stage. Override with `--dynamic_frame_start 0` if you want to include the canonical frame as an anchor during Euler training.

This stage freezes or strongly regularizes the canonical Gaussian scene and optimizes:

- Eulerian velocity-field MLP;
- local motion-grid feature codes;
- optional dynamic/static logits;
- optional adaptive grid split/merge topology.

### Stage C — cycle + SE(3) together

Cycle consistency and local SE(3) coherence are enabled together after:

```bash
--cycle_se3_from_iter 3000
```

This is a local Euler-stage iteration, not the global training iteration. With the defaults, cycle and SE(3) start at global iteration `33000`.

### Optional adaptive grid refinement during Stage B

Adaptive grid split/merge is now an optional mechanism running during Euler training, not a separate final stage.

Enable it with:

```bash
--enable_adaptive_grid
```

and control when it starts with:

```bash
--grid_from_iter 0
```

`grid_from_iter` is also local to the Euler stage. Grid updates use detached motion/rigidity/DINO diagnostics and update only grid topology and local grid assignments. They do not backpropagate into Gaussian positions or the velocity MLP through the score.

## DINOv3 installation as a submodule

DINOv3 is **not vendored** into this patch. Clone it as a Git submodule under the standard `submodules/` folder and install it manually in your conda environment.

From the root of your Gaussian Splatting repo:

```bash
git submodule add https://github.com/facebookresearch/dinov3 submodules/dinov3
git submodule update --init --recursive
```

Then manually install whatever the DINOv3 repository requires, for example:

```bash
cd submodules/dinov3
pip install -e .
cd ../..
```

If the DINOv3 repo requires additional packages or a different install command, follow the DINOv3 README. This patch only assumes that a local repo exists and can be loaded/adapted by `tools/extract_dinov3_features.py`.

## Extracting DINOv3 feature tensors

DINOv3 features are expected as dense tensors per image:

```text
USB_100109/dinov3/cam_000/frame_000000.pt
USB_100109/dinov3/cam_000/frame_000001.pt
...
```

You can extract them as a first preprocessing step:

```bash
python tools/extract_dinov3_features.py \
  --sequence_root /path/to/USB_100109 \
  --rgb_dir rgb \
  --out_dir dinov3 \
  --repo submodules/dinov3 \
  --model_name dinov3_vitl16 \
  --image_size 518
```

Or ask training to try extraction at the beginning:

```bash
python train.py \
  -s /path/to/USB_100109/colmap \
  -m /tmp/usb_dynamic_dino \
  --dynamic_motion \
  --dynamic_sequence_root /path/to/USB_100109 \
  --use_dinov3 \
  --dinov3_extract_on_start \
  --dinov3_repo submodules/dinov3 \
  --disable_viewer
```

If `--use_dinov3` is specified and tensors already exist under `dinov3/`, training will use them. If tensors are missing and `--dinov3_extract_on_start` is not specified, training prints a warning and continues without DINO hints.

DINOv3 maps are not rendered through CUDA. They are projected/sampled offline into frozen per-Gaussian descriptors, then used for:

- DINO-weighted rigidity;
- adaptive grid incoherence scores;
- semantic motion grouping hints.

## Outputs

The output directory keeps standard 3DGS-style outputs and adds dynamic exports:

```text
output_dynamic/
  cfg_args
  cameras.json
  exposure.json
  point_cloud/
    iteration_30000/point_cloud.ply       # static canonical stage
    iteration_40000/point_cloud.ply       # canonical PLY, dynamic state saved beside it
  chkpnt40000.pth                         # full checkpoint with motion field/grid/logits
  gaussian_tracks.pt                      # compact Gaussian trajectories
  dynamic_summary.json
```

The `.ply` remains a canonical/rest 3DGS point cloud. The full dynamic model is in the checkpoint.

The agile trajectory file is:

```text
gaussian_tracks.pt
```

with schema:

```python
{
    "gaussian_ids": LongTensor [N],
    "frame_ids": LongTensor [T],
    "times": FloatTensor [T],
    "positions": FloatTensor [T, N, 3],
    "velocities": FloatTensor [T, N, 3],
    "dynamic_prob": FloatTensor [N, 1] or None,
    "cell_ids": LongTensor [N] or None,
}
```

This is the file you should use for downstream motion analysis and joint estimation. It contains integrated Gaussian positions and instantaneous velocity vectors over time.

Use half precision to reduce size:

```bash
--track_export_dtype float16
```

Export only every Nth frame:

```bash
--track_frame_stride 2
```

## Gradient routing summary

During the Euler stage:

- RGB/SSIM/depth losses backpropagate through advected Gaussian positions into the velocity field.
- Static/speed/rigidity/cycle/SE(3) losses update the velocity field and motion-grid feature codes.
- Dynamic sparsity/binarization losses update only dynamic logits.
- Adaptive grid split/merge uses detached diagnostics and updates only topology/assignments.
- DINOv3 features are frozen hints; they do not receive gradients.
- Canonical Gaussian geometry and appearance are frozen by default during Euler-field training.

The CUDA rasterizer is left unchanged.
